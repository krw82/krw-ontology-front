# KRW Ontology 이탈 방지 전략

*최종 업데이트: 2026-05-23*

---

## 1. 이탈 방지 원칙

### 1.1 핵심 철학

이탈(Churn)은 이벤트가 아니라 **과정**이다. 해지 버튼을 누르기 전에 이미 여러 신호가 존재한다.

1. **조기 탐지:** 이탈 신호를 해지 전에 포착
2. **가치 재확인:** 사용자가 이미 받은 가치를 상기시킴
3. **장벽 제거:** 이탈 사유가 제품 내 문제인 경우 즉시 해결
4. **우아한 해지:** 해지하더라도 긍정적 경험으로 윈백 가능하게
5. **데이터 기반:** 이탈 패턴을 분석하여 예방 체계 고도화

### 1.2 이탈 유형별 대응

| 이탈 유형 | 정의 | 주요 원인 | 대응 전략 |
|----------|------|----------|----------|
| 초기 이탈 | 가입 후 7일 이내 미접속 | 온보딩 실패, 가치 미체험 | 리인게이지먼트 |
| 사용량 이탈 | 유료 전환 후 사용량 지속 감소 | 가치 인식 하락, 대체품 발견 | 사용량 증가 유도 |
| 의도적 해지 | 명시적 해지 요청 | 가격, 기능, 커버리지 | 해지 설문 + 세이브 오퍼 |
| 묵시적 이탈 | 결제 실패 후 복구 불가 | 카드 만료, 잔액 부족 | 결제 복구 시퀀스 |

## 2. 이탈 예측 신호

### 2.1 행동 신호

| 신호 | 정의 | 위험도 | 조치 |
|------|------|--------|------|
| 질문 빈도 감소 | 주간 질문 수 50% 이상 감소 | 높음 | 리인게이지먼트 이메일 |
| 인용구 열기율 하락 | 인용구 열기 / 답변 < 20% | 중간 | 가치 재안내 |
| 세션 시간 단축 | 평균 세션 < 1분 | 높음 | 온보딩 재활성화 |
| 기업 커버리지 에러 | 지원하지 않는 기업 조회 반복 | 중간 | 커버리지 안내 |
| 로그인 빈도 감소 | 주간 로그인 50% 이상 감소 | 높음 | 푸시/이메일 리마인드 |

### 2.2 플랜별 이탈 패턴

| 플랜 | 전형적 이탈 시점 | 주요 패턴 |
|------|----------------|----------|
| Free | 가입 후 1-2주 | 첫 분석 미실행, 재방문 없음 |
| Pro | 결제 후 1-3개월 | 사용량 < 20%/월, 기능 미활용 |
| Power | 결제 후 3-6개월 | 대량 리서치 수요 감소, 대체 |

### 2.3 이탈 위험도 점수

사용자별 이탈 위험도를 자동 계산하여 선제적 대응.

```
위험도 = w1 × (질문빈도변화)
       + w2 × (인용구열기율)
       + w3 × (세션빈도변화)
       + w4 × (사용량_플랜대비비율)
       + w5 × (결제후_경과일수)

위험도 > 0.7 → 즉시 리인게이지먼트
위험도 0.4-0.7 → 모니터링 + 소프트 넛지
위험도 < 0.4 → 정상
```

## 6. 결제 실패 복구

### 6.1 결제 실패 대응 흐름

```
결제 실패 감지
    ↓
D+0: 인앱 알림 "결제에 실패했습니다"
    ↓
D+1: 이메일 "결제 정보 업데이트 필요"
    ↓
D+3: 이메일 "3일 내 업데이트해주세요"
    ↓
D+5: 인앱 + 이메일 "서비스 이용이 곧 중단됩니다"
    ↓
D+7: 서비스 다운그레이드 (Free로 전환)
    ↓
D+14: 최종 이메일 "Free 플랜으로 이용 중입니다"
```

### 6.2 결제 실패 이메일

```
제목: Pro 구독 결제에 실패했습니다

{이름}님, 이번 달 Pro 구독 결제가 정상적으로
처리되지 않았습니다.

가능한 원인:
• 카드 만료 또는 한도 초과
• 결제 정보 변경 필요

결제 정보를 업데이트하시면 Pro 기능이
즉시 복구됩니다.

[결제 정보 업데이트]

업데이트하지 않으시면 7일 후 Free 플랜으로
자동 전환됩니다. 기존 리서치 기록은 유지됩니다.
```

## 7. 리텐션 KPI

### 7.1 핵심 리텐션 지표

| 지표 | 정의 | 목표 |
|------|------|------|
| 월간 유료 유지율 | MRR Retention Rate | > 95% |
| 월간 로그인 유지율 | MAU Retention | > 60% |
| Day-7 재방문율 | 가입 후 7일 내 재방문 | > 30% |
| Day-30 재방문율 | 가입 후 30일 내 재방문 | > 20% |
| Free→Pro 전환율 | Free 한계 도달 후 Pro 가입 | > 5% |
| Pro→Power 업셀율 | Pro 한계 도달 후 Power 가입 | > 10% |
| 해지율 (Gross Churn) | 월간 해지 / 총 유료 | < 5% |
| 순 수익 유지율 (NRR) | 확장 포함 순유지율 | > 100% |

### 7.2 코호트 분석 체계

| 코호트 | 정의 | 분석 항목 |
|--------|------|----------|
| 가입 코호트 | 같은 주/월에 가입한 사용자 | 주간/월간 리텐션 곡선 |
| 플랜 코호트 | 같은 플랜의 유료 사용자 | 플랜별 리텐션, 사용량 추이 |
| 활성화 코호트 | 활성화 달성 vs 미달성 | 장기 리텐션 차이 |
| 채널 코호트 | 같은 획득 채널의 사용자 | 채널별 리텐션 품질 |

### 7.3 분석 이벤트

| 이벤트 | 발생 조건 | 속성 |
|--------|----------|------|
| `subscription_cancelled` | 해지 완료 | `plan`, `reason`, `months_active`, `analyses_used` |
| `subscription_saved` | 세이브 오퍼 수락 | `plan`, `save_offer_type` |
| `payment_failed` | 결제 실패 | `plan`, `failure_reason` |
| `payment_recovered` | 결제 복구 | `plan`, `days_to_recover` |
| `winback_email_sent` | 윈백 이메일 발송 | `days_since_cancel`, `offer_type` |
| `winback_converted` | 윈백 이메일 후 복귀 | `days_since_cancel`, `offer_type` |

## 8. 이탈 방지 캘린더

### 8.1 일간 자동화

| 시간 | 작업 |
|------|------|
| 매일 | 결제 실패 감지 및 알림 |

|------|------|

| 시점 | 작업 |
|------|------|

## 9. 이탈 분석 프레임워크

### 9.1 해지 사유 분류 및 대응

| 사유 | 비중 예상 | 예방 전략 | 대응 |
|------|----------|----------|------|
| 가격 | 25-30% | 가격 대비 가치 명확화 | 할인 오퍼 |
| 사용량 부족 | 20-25% | 온보딩 강화, 사용량 유도 | 활용 팁, 무료 연장 |
| 기업 미지원 | 15-20% | 커버리지 확대 | 알림 신청 |
| 답변 품질 | 15-20% | 품질 개선, 프롬프트 가이드 | 피드백 수집 |
| 워크플로우 | 10-15% | UX 개선 | 사용성 피드백 |
| 경쟁사 전환 | 5-10% | 차별화 강화 | 기능 비교 안내 |

```
    ↓

    ↓

```
