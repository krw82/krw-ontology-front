# 추천 프로그램 설계

*최종 수정: 2026-05-23*

---

## 1. 추천 프로그램 전략 개요

### 1.1 목표

- 사용자 기반 유기적 성장 촉진
- 획득 비용(CAC) 절감: 추천 가입자의 CAC는 유료 채널 대비 50-80% 낮음
- Pro 전환율 향상: 추천 가입자는 일반 가입자 대비 2-3x 높은 전환율
- 한국 투자자 커뮤니티 내 입소문 확산

### 1.2 타겟 추천 행동

| 행동 | 정의 | 우선순위 |
|------|------|---------|
| 1차 | 활성 사용자가 친구/동료에게 제품 링크 공유 | 최우선 |
| 2차 | Pro 사용자가 커뮤니티/뉴스레터에 추천 | 높음 |
| 3차 | 공시 분석 결과를 소셜/커뮤니티에 공유 | 중간 |

### 1.3 원칙

- **쌍방 인센티브:** 추천인과 피추천인 모두 혜택
- **단순 구조:** 규칙이 직관적이어야 참여율이 높음
- **가치 미터 기반:** 분석 횟수가 핵심 가치이므로 추가 분석 권수가 최적 인센티브
- **프리미엄 모델 일관성:** 무료 플랜 내에서만 인센티브 제공 (Pro 전환 유도)

## 2. 추천 프로그램 구조

### 2.1 인센티브 설계

**v1 추천 보상:**

| 대상 | 혜택 | 형태 |
|------|------|------|
| 추천인 | 무료 분석 5회 추가 | 당월 무료 한도 증가 |
| 피추천인 | 무료 분석 15회 (기본 10 + 5) | 첫 달 한도 증가 |

**보상 로직:**
- 추천인 보상: 피추천인이 첫 분석을 완료한 시점에 지급
- 피추천인 보상: 가입 즉시 적용
- 월간 누적: 추천 10명 = 당월 무료 한도 10 + 50 = 60회
- 한도 초과 시: 추가 추천 보상은 다음 달로 이월

**v2 업그레이드 (런치 후 3-6개월):**

| 대상 | 혜택 | 조건 |
|------|------|------|
| 추천인 | Pro 1개월 무료 | 피추천인 3명이 Pro 전환 시 |
| 추천인 | Power 1개월 무료 | 피추천인 10명이 Pro 전환 시 |

### 2.2 추천 코드 시스템

**추천 링크 형식:**
```
https://krwontology.com/?ref={user_code}
```

**사용자 코드 생성 규칙:**
- 형식: 8자리 영숫자 (예: `KR7X2M9P`)
- 가입 시 자동 생성
- 변경 불가 (일관성 유지)
- 대소문자 구분 없음

**추천 링크 진입 페이지:**
- 일반 홈페이지와 동일
- 쿠키에 `ref` 코드 저장 (30일 유효)
- 가입 시 `ref` 코드를 `analytics_events`에 기록
- 피추천인에게 "추천으로 가입하여 분석 15회 제공" 배너 표시

### 2.3 추천 트리거

**추천 제안이 표시되는 시점:**

| 트리거 | 위치 | 메시지 |
|--------|------|--------|
| 첫 답변 완료 후 | 채팅 페이지 하단 | "이 분석을 친구와 공유하고 무료 분석 5회 더 받기" |
| 인용 첫 열람 후 | 인용 패널 | "근거 경로를 공유해보세요" |
| 무료 한도 80% 도달 | 한도 알림 | "추천으로 추가 분석 확보하기" |
| 무료 한도 100% 도달 | 한도 도달 화면 | "추천 1명당 분석 5회 추가" |
| 주간 리포트 이메일 | 이메일 | "이번 주 추천 현황" |
| Pro 업그레이드 후 | 설정 페이지 | "친구 추천하고 Pro 1개월 무료" |

## 3. 바이럴 루프 설계

### 3.1 바이럴 루프 구조

```
사용자 A가 분석 완료
   ↓
"이 분석 공유하기" 버튼 클릭
   ↓
공유 링크 생성 (A의 ref 코드 포함)
   ↓
A가 링크를 커뮤니티/메신저/소셜에 공유
   ↓
B가 링크 클릭 → 쿠키에 ref 저장
   ↓
B가 가입 → "추천으로 분석 15회" 배너
   ↓
B가 첫 분석 완료
   ↓
A에게 "분석 5회 추가" 알림
   ↓
A가 더 많이 공유
```

### 3.2 공유 가능한 콘텐츠 유형

**유형 1: 분석 결과 공유**

```
형식: 공유 링크 + 미리보기 카드
내용: 질문 요약 + 답변 요약 + "KRW Ontology에서 근거 확인하기"
예시:
  "NVDA 데이터센터 성장 요인을 최근 공시 기준으로 분석한 결과"
  [요약 2-3문장]
  "출처와 근거 경로를 KRW Ontology에서 확인하세요"
  → 공유 링크
```

**유형 2: 직접 추천 링크**

```
형식: 단순 URL
메시지 템플릿 (선택):
  - "공시 원문 근거가 남는 기업 리서치 AI, 무료 분석 15회로 시작"
  - "10-K를 질문으로 분석하는 AI, 출처가 보이는 답변"
  - "기업 공시 리서치 도구 추천, 이 링크로 가입하면 분석 15회 무료"
```

**유형 3: 질문 템플릿 공유**

```
형식: 특정 질문 링크
예시:
  "이 질문을 KRW Ontology에서 실행해보세요:
   'AAPL 서비스 매출 리스크가 어느 사업 활동과 연결되는지 보여줘'"
  → 추천 링크 + 프리필된 질문
```

### 3.3 바이럴 계수 (K-factor) 타겟

| 지표 | 정의 | 타겟 (6개월) |
|------|------|-------------|
| K-factor | 초대당 가입 수 × 초대 비율 | 0.3-0.5 |
| 추천 참여율 | 활성 사용자 중 추천 코드 공유 비율 | 10-15% |
| 추천 가입율 | 추천 링크 클릭 → 가입 | 15-25% |
| 추천 활성화율 | 추천 가입 → 첫 분석 완료 | 40-50% |
| 추천 Pro 전환율 | 추천 가입 → Pro 전환 | 8-12% |

## 5. 추적 및 측정

### 5.1 데이터베이스 스키마

**추천 테이블:**

```sql
referrals (
  id          UUID PRIMARY KEY,
  referrer_id UUID NOT NULL REFERENCES auth.users(id),
  code        TEXT NOT NULL UNIQUE,       -- 사용자 추천 코드
  created_at  TIMESTAMPTZ NOT NULL
)

referral_events (
  id              UUID PRIMARY KEY,
  referral_code   TEXT NOT NULL,          -- 추천 코드
  referred_user_id UUID REFERENCES auth.users(id),
  event_type      TEXT NOT NULL,          -- 'link_clicked', 'signed_up', 'first_analysis', 'converted_pro'
  created_at      TIMESTAMPTZ NOT NULL
)

referral_rewards (
  id              UUID PRIMARY KEY,
  user_id         UUID NOT NULL REFERENCES auth.users(id),
  reward_type     TEXT NOT NULL,          -- 'extra_analyses', 'free_month'
  reward_amount   INT NOT NULL,
  source_event    TEXT NOT NULL,          -- 'referral_signup', 'referral_first_analysis', 'referral_pro_conversion'
  created_at      TIMESTAMPTZ NOT NULL
)
```

### 5.2 추적 이벤트

| 이벤트 | 발생 시점 | 속성 |
|--------|---------|------|
| `referral_link_generated` | 사용자가 추천 링크 조회 | `code` |
| `referral_link_shared` | 공유 버튼 클릭 | `code`, `channel` |
| `referral_link_clicked` | 추천 링크 방문 | `code`, `source` |
| `referral_signed_up` | 추천 경로로 가입 완료 | `code`, `referred_user_id` |
| `referral_first_analysis` | 피추천인 첫 분석 완료 | `code`, `referred_user_id` |
| `referral_reward_granted` | 보상 지급 | `code`, `reward_type`, `amount` |
| `referral_pro_converted` | 피추천인 Pro 전환 | `code`, `referred_user_id` |

### 5.3 분석 대시보드

## 6. 안티프루드

### 6.1 남용 방지

| 위험 | 대응 |
|------|------|
| 자기 추천 (다중 계정) | 동일 IP, 디바이스, 결제 수단 감지 |
| 보냇 계정 양산 | 가입 후 24시간 이내 첫 분석 필요 |
| 보상 쌓기 | 월간 보상 상한 (월 50회 추가) |
| 가짜 가입 | 이메일 인증 + Google SSO 필수 |

### 6.2 정책

- 1인 1추천코드
- 피추천인은 30일 이내 가입 시에만 추천으로 인정
- 보상은 피추천인의 첫 분석 완료 후 지급 (가입만으로는 불충분)
- 프로모션 변경 시 30일 전 공지
- 악용 감지 시 계정 경고 후 반복 시 정지

## 7. 실행 로드맵

### Phase 1: 기본 추천 (런치 동시, 0-2개월)

1. 추천 코드 생성 로직 구현
2. 가입 시 `ref` 파라미터 추적
3. 추천 링크 복사 UI
4. 기본 보상 로직 (추천인 +5, 피추천인 +5)
5. 추천 대시보드 (설정 페이지)

### Phase 2: 인앱 트리거 (2-4개월)

6. 답변 완료 후 공유 프롬프트
7. 한도 도달 시 추천 제안
8. 공유 시트 (카카오톡/URL/이메일)
9. 분석 결과 공유 기능

### Phase 3: 고급 보상 (4-6개월)

10. Pro 전환 기반 보상 (v2)
11. 추천 리더보드 (선택)
12. 추천 캠페인 (특정 기간 보상 2x)

## 9. 요약

**핵심 설계 원칙:**
- 쌍방 인센티브: 추천인 +5회, 피추천인 +5회
- 가치 미터 기반: 추가 분석 권수가 가장 매력적인 보상
- 바이럴 루프: 분석 완료 → 공유 → 가입 → 보상 → 더 많은 공유
- 한국 채널 최적화: 카카오톡 공유 우선

**성공의 핵심:**
- 추천이 "홍보"가 아닌 "유용한 분석 공유"로 느껴져야 함
- 공유하는 콘텐츠(분석 결과) 자체가 가치가 있어야 바이럴이 작동
- 6개월 내 전체 가입의 25%가 추천 경로에서 오는 것이 목표
