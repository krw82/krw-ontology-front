# 회원가입 최적화 전략

*최종 수정: 2026-05-23*

---

## 1. 가입 최적화 개요

### 1.1 목표

- 가입 완료율 극대화 (CTA 클릭 → 가입 완료 65% 이상)
- 첫 분석까지의 시간 단축 (가입 후 3분 이내)
- 가입→활성화 전환율 45% 달성 (7일 내 답변 완료 + 인용 열기)
- 가입 마찰 최소화 (필드 수 0개, 클릭 2회 이내)

### 1.2 현재 가입 흐름 분석

```
홈페이지 CTA → /login → Google OAuth → 콜백 → /chat
```

**강점:**
- Google SSO 단일 경로 (v1 목표와 일치)
- 추가 필드 없음 (이름, 역할, 포트폴리오 등 수집 안 함)
- OAuth 콜백 후 원래 경로로 복귀

**개선 필요:**
- 비로그인 사용자가 홈페이지에서 명시적 CTA를 볼 수 없음
- 로그인 페이지의 가치 제안이 불명확할 수 있음
- 가입 완료 후 온보딩/첫 질문 유도가 약함
- 가입 성공 피드백이 없음

## 2. 가입 플로우 설계

### 2.1 이상적인 가입 플로우

```
Step 1: CTA 클릭
  "무료로 첫 분석 시작" → /login?next=/chat

Step 2: 로그인 페이지
  가치 리마인더 + Google 로그인 버튼 1개
  (2초 이내 클릭 가능)

Step 3: Google OAuth
  계정 선택 → 권한 승인 (1회만)
  (이미 Google 로그인 상태면 자동)

Step 4: 콜백 + 리다이렉트
  /auth/callback → next 파라미터 경로로 이동

Step 5: 첫 경험
  /chat 또는 /companies → 스타터 질문 → 첫 분석
```

### 2.2 마찰 원천 및 제거 방안

| 마찰 원천 | 제거 방안 |
|-----------|----------|
| "무엇을 하는 서비스인가?" | 로그인 페이지에 간결한 가치 리마인더 |
| "내 정보를 왜 주나?" | Google SSO만, 추가 필드 없음 명시 |
| "결제를 해야 하나?" | "무료 분석 10회 · 카드 불필요" 명시 |
| "어떤 회사가 되나?" | 로그인 후 지원 회사 바로 안내 |
| "무엇을 물어봐야 하나?" | 스타터 질문 3-5개 자동 제안 |

## 3. 로그인 페이지 최적화

### 3.1 페이지 구조

```
┌──────────────────────────────────────┐
│                                      │
│         [KRW Ontology 로고]          │
│                                      │
│    근거가 보이는 기업 분석 AI          │
│                                      │
│    공시 원문에서 근거를 찾아           │
│    답변을 정리합니다.                  │
│                                      │
│    ┌────────────────────────────┐    │
│    │  [G] Google로 계속하기      │    │
│    └────────────────────────────┘    │
│                                      │
│    무료 분석 10회/월 · 카드 불필요    │
│                                      │
│    ────────────────────────────      │
│    가입 시 서비스 약관,               │
│    개인정보처리방침에 동의합니다.      │
│                                      │
└──────────────────────────────────────┘
```

### 3.2 핵심 원칙

- **단일 버튼:** Google 로그인만, 이메일/비밀번호 입력 없음
- **가치 리마인더:** 로그인 페이지에서도 제품 가치를 한 문장 전달
- **무료 강조:** "무료 분석 10회 · 카드 불필요" 텍스트
- **법적 고지:** 약관/개인정보 링크 (버튼 아래)
- **로고:** 상단에 브랜드 로고로 소속감 제공

### 3.3 소셜 로그인 확장 계획

| 시기 | 로그인 방식 | 이유 |
|------|-----------|------|
| v1 (런치) | Google만 | 구현 단순, 한국 투자자 점유율 높음 |
| v2 (3개월 후) | + 카카오계정 | 한국 서비스 기본, 낮은 진입 장벽 |
| v3 (6개월 후) | + Apple | iOS 사용자, 프라이버시 민감층 |

**카카오계정 추가 시 고려사항:**
- 한국 사용자의 압도적 보유율
- 모바일에서 카카오톡 앱으로 원클릭 로그인
- 구현: Supabase OAuth provider 추가
- 우선순위: Google 사용자 수 데이터 확인 후 결정

## 4. 가입 후 온보딩

### 4.1 첫 경험 설계 (First-Run Experience)

**목표:** 가입 후 3분 이내에 첫 질문 제출, 5분 이내에 답변 완료

**가입 후 플로우:**

```
1. 리다이렉트 → /chat (또는 next 파라미터 경로)

2. 채팅 빈 상태 화면:
   ┌──────────────────────────────────────┐
   │ 환영합니다! 첫 분석을 시작해보세요     │
   │                                      │
   │ 추천 질문 (글로벌):                    │
   │ • "NVDA 데이터센터 성장 요인을..."    │
   │ • "AMZN 클라우드 이익률이 왜..."      │
   │ • "AAPL 서비스 매출 리스크가..."      │
   │                                      │
   │ 또는 회사를 선택하세요:                │
   │ [회사 검색...]                        │
   └──────────────────────────────────────┘

3. 회사 선택 시 (또는 /companies에서 진입):
   ┌──────────────────────────────────────┐
   │ NVDA (NVIDIA)                        │
   │                                      │
   │ 이 회사에 대해 자주 묻는 질문:         │
   │ • "매출 성장 요인을 분해해줘"          │
   │ • "데이터센터 vs 게임 세그먼트 비교"   │
   │ • "주요 리스크 요인은?"               │
   │ • "AI 관련 매출 기여는?"              │
   │ • "다음 분기 전망은?"                 │
   └──────────────────────────────────────┘

4. 질문 제출 → 답변 생성 중:
   진행 상태 표시 + "근거를 찾고 있습니다" 안내

5. 답변 완료 후:
   ┌──────────────────────────────────────┐
   │ [답변 내용]                          │
   │                                      │
   │ 📌 근거 경로 (3개)                    │
   │ → 출처를 클릭하면 원문을 확인할 수     │
   │    있습니다.                          │
   │                                      │
   │ [인용 열기] ← 첫 인용 열기 유도        │
   └──────────────────────────────────────┘
```

### 4.2 스타터 질문 세트

**글로벌 컨텍스트 (티커 미선택 시):**

```
1. "NVDA 데이터센터 성장 요인을 최근 공시 기준으로 분해해줘"
2. "AMZN 클라우드 이익률이 왜 바뀌었는지 근거와 함께 정리해줘"
3. "AAPL 서비스 매출 리스크가 어느 사업 활동과 연결되는지 보여줘"
4. "MSFT 클라우드 성장 전략을 최근 공시에서 분석해줘"
5. "GOOGL 광고 매출 동인을 최근 10-K에서 확인해줘"
```

**티커 컨텍스트 (회사 선택 시):**

```
{회사명}에 대해 자주 묻는 질문:
1. "{TICKER} 매출 성장 요인을 최근 공시 기준으로 분해해줘"
2. "{TICKER} 영업이익률 변화 원인을 세그먼트별로 보여줘"
3. "{TICKER} 최근 10-K에서 신규 리스크 요인은?"
4. "{TICKER} 세그먼트별 수익성을 공시에서 비교해줘"
5. "{TICKER} 주력 사업의 성장 전망을 공시에서 확인해줘"
```

### 4.3 활성화 마일스톤

| 단계 | 이벤트 | 유도 방법 |
|------|--------|----------|
| 1 | 첫 질문 제출 | 스타터 질문 클릭 유도 |
| 2 | 첫 답변 완료 | 진행 상태 + 완료 축하 |
| 3 | 첫 인용 열기 | 답변 후 "근거 경로 확인하기" 하이라이트 |
| 4 | 두 번째 질문 | "다른 질문도 해보세요" 프롬프트 |
| 5 | Day-7 재방문 | 이메일 리마인더 |

## 5. 가입 마찰 최소화

### 5.1 데스크톱 최적화

| 항목 | 현재 | 개선안 |
|------|------|--------|
| CTA에서 로그인까지 | 명확한 경로 | `next` 파라미터로 원래 경로 보존 |
| 로그인 후 이동 | `/chat` | CTA 출발점으로 복귀 |
| 추가 필드 | 없음 (양호) | 유지 |
| 이메일 인증 | 불필요 (Google SSO) | 유지 |

### 5.2 모바일 최적화

| 항목 | 개선안 |
|------|--------|
| CTA 크기 | 48px 이상 터치 타겟 |
| 로그인 버튼 | 전체 너비, 큰 터치 영역 |
| Google OAuth | 모바일 브라우저 → 앱 전환 최소화 |
| 키보드 | 입력 필드 없으므로 키보드 미노출 |
| 로딩 | 스켈레톤 UI로 체감 대기시간 단축 |

### 5.3 비로그인 사용자 경험

**현재 문제:** 비로그인 사용자가 홈페이지에서 제품을 체험할 방법이 명확하지 않음.

**개선안:**

1. **데모 경험 (비로그인):**
   - 홈페이지 데모 폼을 클릭하면 → "무료로 시작하려면 로그인하세요" 모달
   - 모달에서 바로 Google 로그인

2. **회사 탐색 (비로그인):**
   - `/companies` 접근 시 회사 목록은 볼 수 있음
   - "이 회사 분석하기" 클릭 시 → 로그인 프롬프트
   - 로그인 후 → 선택한 회사 컨텍스트로 채팅 진입

3. **유스케이스 페이지 (비로그인):**
   - 전체 읽기 가능
   - "이 분석 해보기" CTA → 로그인 → 프리필된 질문

## 6. 가입 전환율 최적화

### 6.1 심리적 장벽 해소

| 장벽 | 해소 방안 |
|------|----------|
| "결제를 요구할 것 같다" | "무료 10회 · 카드 불필요" 반복 |
| "스팸 메일이 올 것 같다" | "광고 이메일 없음" 또는 "필수 알림만" 명시 |
| "무엇을 해야 할지 모르겠다" | 스타터 질문으로 "생각할 필요 없이" 시작 |
| "내 회사가 없을 수 있다" | 지원 회사 먼저 확인 가능 (2차 CTA) |
| "시간이 오래 걸릴 것 같다" | "질문 후 30초 이내 답변" 안내 |

### 6.2 긴급성/희소성 부여

- "무료 분석 10회/월" — 월간 한도가 자연적 희소성
- "이번 달 무료 분석 X회 남음" — 대시보드에 남은 횟수 표시
- 한도 도달 시 자연스러운 업그레이드 압력

### 6.3 A/B 테스트 후보

| 테스트 | 가설 | 측정 지표 |
|--------|------|----------|
| CTA: "무료로 시작" vs "Google로 시작" | SSO 명시가 가입율 높이는가? | 로그인 완료율 |
| 로그인 페이지 가치 문구 유무 | 가치 리마인더가 이탈 감소시키는가? | 로그인 버튼 클릭률 |
| 스타터 질문 수: 3 vs 5 | 질문 수가 첫 질문 제출률에 영향? | 첫 질문 제출율 |
| 빈 상태: 질문 vs 회사 선택 | 먼저 회사를 고르는 것이 더 나은가? | 활성화율 |
| 환영 이메일 즉시 vs 없음 | 환영 이메일이 Day-7 리텐션에 영향? | Day-7 재방문율 |

## 7. 이메일 인증 및 보안

### 7.1 가입 보안

- Google SSO: Google의 이메일 인증에 의존
- 추가 이메일 인증 불필요 (v1)
- Rate limiting: 동일 IP에서 시간당 가입 시도 5회 제한
- Suspicious activity: 빠른 연속 가입 시 CAPTCHA

### 7.2 세션 관리

- Supabase JWT 기반 세션
- 세션 만료: 7일 (자주 쓰는 사용자는 자동 연장)
- 동시 로그인: 허용 (모바일+데스크톱)
- 로그아웃: 명시적 로그아웃 버튼 항상 노출

## 8. 가입 경로별 최적화

### 8.1 경로별 가입 흐름

| 진입 경로 | CTA 문구 | 가입 후 이동 |
|-----------|---------|------------|
| 홈페이지 | 무료로 첫 분석 시작 | /chat (글로벌 스타터) |
| /companies/{ticker} | {회사명} 분석 시작 | /chat?ticker={TICKER} |
| /use-cases/* | 이 분석 해보기 | /chat (관련 질문 프리필) |
| /resources/* | 직접 체험하기 | /chat (관련 질문 프리필) |
| 추천 링크 (?ref=X) | 무료 분석 15회로 시작 | /chat + 추천 배너 |
| 이메일 | 질문 실행하기 | /chat (질문 프리필) |

### 8.2 next 파라미터 보존

모든 CTA는 `?next={목적지}`를 포함하여 로그인 후 원래 의도한 경로로 복귀:

```
/home → CTA → /login?next=/chat
/companies/AAPL → CTA → /login?next=/chat?ticker=AAPL
/use-cases/filing-analysis → CTA → /login?next=/chat?q=...
```

## 9. 측정 및 모니터링

### 9.1 가입 퍼널 이벤트

```
cta_clicked          → CTA 클릭 (cta_id, cta_label, destination)
login_started        → Google OAuth 시작
login_completed      → 콜백 성공 (is_new_user, next_path)
question_submitted   → 첫 질문 제출 (source: 'starter')
answer_completed     → 첫 답변 완료
citation_opened      → 첫 인용 열기
```

### 9.2 코호트 분석

| 코호트 | 측정 | 타겟 |
|--------|------|------|
| 가입일 기준 | Day-0 활성화율 | 45% |
| 가입일 기준 | Day-7 리텐션 | 25% |
| 가입일 기준 | Day-30 활성 | 15% |
| 진입 경로별 | 가입→활성화 | 30-50% (경로별) |
| 디바이스별 | 가입→활성화 | Desktop 50%, Mobile 40% |
| 추천 vs 일반 | 활성화율 | 추천 50%, 일반 40% |

## 11. 요약

**가입 최적화의 핵심은 "마찰 제거"와 "즉각적 가치"다.**

**핵심 원칙:**
- 클릭 2회 이내 가입 완료 (CTA → Google 로그인)
- 추가 필드 제로 (Google SSO만)
- 가입 후 3분 이내 첫 분석 완료
- 스타터 질문으로 "무엇을 물어볼까" 고민 제거

**성공 기준:**
- CTA→가입 완료율 65%
- 가입→첫 분석 완료율 45%
- 가입→Day-7 리텐션 25%
- 가입 전환 시간 중앙값 60초 이내
