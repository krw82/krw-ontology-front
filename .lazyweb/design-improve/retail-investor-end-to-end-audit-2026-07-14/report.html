TL;DR

가장 큰 문제는 기능 부족이 아니라, 첫 행동과 다음 판단을 사용자가 스스로 해석해야 한다는 점입니다.

  • 홈의 질문창처럼 보이는 영역은 실제 입력이 불가능합니다. 핵심 가치 직전에 가장 강한 오해를 만듭니다.
  • 같은 기능의 이름과 순서가 공개·로그인·사이드바에서 달라집니다. 사용자는 새 화면마다 제품을 다시 학습합니다.
  • 회사 화면은 구조를 보여주지만 “그래서 지금 무엇을 봐야 하나”를 요약하지 않습니다. 초보자는 좋은 질문을 만들기 전에 멈출 수 있습니다.
  • 한도와 가격은 기능을 설명하지만 실제 사용 가능량을 설명하지 않습니다. 막힌 뒤에야 비용 구조를 배우게 됩니다.
  • 기술 오류 문구와 13F 데스크톱 레이아웃은 즉시 수정해야 할 신뢰 문제입니다.

권장 순서: 오해·신뢰 결함(P0) → 하나의 진입 언어와 회사 판단 브리프(P1) → 한도 투명성(P1) → 모바일·보조 흐름 정리(P2).

Method & scope

어떻게 점검했는가

  • Lazyweb의 design-improve 절차로 현재 화면 캡처, 실서비스 레퍼런스, 1–5개 개선 프로그램, ASCII 와이어프레임 순서로 감사했습니다.
  • Open Design의 Hick·Pareto·recognition over recall, 상태 커버리지, 오류 회복, WCAG 2.2 AA, 모션 절제 기준을 적용했습니다.
  • 홈, 첫 리서치 선택, 회사 상세, 채팅, 종목 발굴, 구루, 기관 13F, 관심종목, 가격·결제, 질문 그래프를 데스크톱과 모바일에서 확인했습니다.
  • 화면 관찰은 코드에서 다시 확인했습니다. 추정과 확인된 결함을 이슈 표에서 구분했습니다.
도구 투명성: 이 세션에는 Lazyweb의 실시간 레퍼런스 DB 커넥터가 노출되지 않아, 플러그인의 감사 절차는 그대로 사용하고 레퍼런스는 공식 사이트를 실시간 브라우저로 직접 캡처했습니다.
테스트 환경과 해석 주의사항
  • 인증 우회와 정적 E2E 카탈로그를 사용했습니다. 회사 목록의 AMZN 단일 노출은 운영 데이터 커버리지 문제로 판정하지 않았습니다.
  • 채팅·종목 발굴의 주간 한도 카드는 개발 미리보기 상태입니다. 운영에서 실제로 한도가 소진됐다는 주장이 아니라, 그 상태의 UX를 평가한 것입니다.
  • Next.js 개발 버블은 제품 UI에서 제외했습니다.
  • 이 보고서 작성 과정에서 제품 코드는 수정하지 않았습니다. 이전 요청에 따라 리서치 노트북과 와이드 리서치는 구현 변경 범위에서 제외합니다.

What already works

현재 디자인에서 반드시 보존할 것

  • 차별화가 명확합니다. 출처 → 사업 맥락 → 근거 있는 답변의 흐름을 홈에서 시각적으로 보여줍니다.
  • 첫 리서치 선택은 Hick의 법칙에 맞습니다. 선택지를 3개로 줄이고 회사 분석을 추천합니다.
  • 투자 조언과 리서치를 구분합니다. 구루는 실제 조언자가 아닌 AI 관점이고, 13F는 지연된 보유 스냅샷임을 설명합니다.
  • 모바일에서 수평 오버플로는 발견되지 않았습니다. 기본 반응형 골격은 안정적입니다.
  • 질문·관심종목·보유 연결은 제품의 장기 방어력입니다. 문제는 기능이 아니라 시작 순서와 위계입니다.

01. 홈을 ‘보여주는 데모’에서 ‘한 회사로 시작하는 실제 행동’으로

목표: 첫 10초 안에 사용자가 무엇을 입력하고 어떤 결과를 받는지 이해하게 합니다.

  • 재방문자는 최근 회사의 ‘이어서 보기’를 최상단에 노출합니다.
