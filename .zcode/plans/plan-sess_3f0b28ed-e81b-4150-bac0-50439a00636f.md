# 완료 리서치 lane 분리 구현 계획

## 검증 반영사항
- **revision trigger 이미 존재** — `trg_pulse_feed_revision_agent_runs`가 agent_run 완료 시 즉시 bump. 새 migration 불필요 (계획 #4 제거).
- **`source_event_id` 이미 존재** — FK 없지만 값 저장됨. 배지 연결에 사용 가능.
- **`item_key`가 phase별로 분리** — active/completed가 다른 키. delta 전환 자연스러움.
- **`finished_at` 인덱스 부재** — 24시간 필터 쿼리용 인덱스 migration 필요.

- `buildRefreshSummary`: completed 카드가 candidate count에 false-positive로 잡히지 않도록 `knownIds` 처리는 동일 (active↔completed 이동은 update로 처리됨 — 기존 주석 L81-82 의도와 일치)

### 1-3. `src/lib/pulse/composer.ts`
- `createUnavailablePulseFeed`에 `completed_analysis_items: []` 추가 (기본값)

  - `visibleCompletedAnalysis` (최대 3개, 24시간 필터는 analysis.ts에서 처리)
  - `completed_analysis_items: toPublicItems(visibleCompletedAnalysis)` 반환값 추가
  - `item_versions` 빌더 호출에 `completed_analysis_items` 전달

## Phase 2: 완료 분석 소스 (24시간 필터)

### 2-1. `src/lib/pulse/sources/analysis.ts`
- 완료 분석에 24시간 필터 추가:
  ```ts
  // 기존 30일 cutoff는 세션 조회용으로 유지
  // 완료 카드는 finished_at >= now - 24h만 candidate로
  ```
- `buildAnalysisCandidates`에서 `completed` phase인 경우 `finished_at`이 24시간 이내인지 체크
- `expires_at`을 24시간으로 단축 (기존 30일 → 24시간, L133-135)
- 실패 분석(`failed`)은 candidate에서 제외 (현재는 포함됨)

### 2-2. `src/lib/pulse/item-state.ts`
- 완료 카드의 "결과 열람" 처리: 기존 `reviewed_at` 재사용
- `applyPulseItemStates`는 이미 `reviewed_at` 설정 시 `state: "reviewed"` 처리 → 완료 카드가 review mutation 후 다음 동기화에서 candidate pool에서 자연스럽게 제외됨 (composer에서 completed를 별도 pool로 분리하므로)
