## 뉴스성 사전 필터(LLM 거부권) 구현 계획

### 검증된 프롬프트 v2를 웹 수집 파이프라인에 통합

**목표**: IR 페이지 메타데이터/네비게이션/주가 스크래핑을 뉴스로 합성하는 가짜 이슈를 근원에서 차단. 테스트 결과 87.5% 정확도 검증 완료.

---

### 1단계: 새 파일 — `src/lib/market-issues/news-classifier.ts`

검증된 프롬프트 v2를 캡슐화한 독립 모듈.

**내용**:
- `classifyAsNewsEvent(url, title, body)` 함수 — ZAI GLM-5.1 호출 (기존 `config.zaiBaseUrl`, `config.zaiApiKey`, `config.composerModel` 재사용)
- `REJECT_PROMPT_V2` 상수 (테스트에서 87.5% 정확도 검증된 프롬프트 그대로)
  - 승인 조건 9개 (실적/M&A/신제품/파트너십/규제/마일스톤 등)
  - 거부 조건 8개 (IR 페이지/경영진 소개/주가 위젯/과거 역사적 이벤트 등)
  - URL 힌트 (/stock-quote, /leadership, /investors/ 등 경로 패턴)
- 반환: `{ isNewsEvent: boolean, confidence: number, reason: string, eventType: string }`
- `thinking: { type: "disabled" }` 적용 — reasoning 모델 토큰 낭비 방지 (prod enrichment의 `requestComposerOutput`이 이미 이 패턴 사용 중)
- `max_tokens: 4096` (reasoning 모델 대응, 테스트에서 0 에러 확인)

**비용 절감 가드** (LLM 호출 전 단순 체크):
- 본문 200자 미만 → LLM 호출 없이 `false` (내용 부족)
- `classifySignal` 결과가 이미 "high" + event_type_hint 있으면 → LLM 호출 스킵하고 `true` (신뢰)

### 2단계: `src/lib/market-issues/web-ingestion.ts` 수정

**삽입 지점**: `processDetailMessage` 함수 내, `assessMarketWebArticleQuality` (line ~480) 통과 후, `persistWebSourceItem` (line ~508) 직전.

```ts
// 기존 규칙 기반 품질 게이트
const quality = assessMarketWebArticleQuality(article, profile);
if (!quality.accepted) {
  // ... 기존 ignored 처리 ...
  return;
}

// === 신규: LLM 뉴스성 사전 필터 ===
const newsCheck = config.newsClassifierEnabled
  ? await classifyAsNewsEvent(article.canonicalUrl, article.title, article.body)
  : { isNewsEvent: true, confidence: 1, reason: "classifier_disabled" };

if (!newsCheck.isNewsEvent) {
  // 기존 rejected 경로 재사용 — candidate.status="ignored", quality_status="rejected"
  await markCandidateRejected(candidateId, {
    reason: "not_news_event",
    classifierReason: newsCheck.reason,
    classifierConfidence: newsCheck.confidence,
  });
  return; // market_source_items 행 생성 안 됨 → 이슈/enrichment 전부 스킵
}
// === 필터 종료 ===

// 기존: persistWebSourceItem(...)
```

**기대 효과**: 거부된 항목은 `market_source_items` 행 자체가 생성되지 않아:
- correlate 큐 메시지 없음
- 이슈 생성 없음
- enrichment 작업 큐잉 없음
- 미디어 추출(vision LLM) 스킵
- compose LLM 호출 스킵
- **원문 1건당 약 2000 토큰(classifier) vs 15000+ 토큰(전체 enrichment) 절감**

### 3단계: config에 플래그 추가 — `src/lib/market-issues/config.ts`
