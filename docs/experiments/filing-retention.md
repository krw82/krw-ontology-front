# 공시 알림 리텐션 실험 계획

이 기능은 공시가 발생할 때 가치가 생기는 제품이다. 따라서 일반 D7만으로
승패를 정하지 않고, 첫 유효 공시를 연 사용자가 두 번째 유효 공시도 여는
`next-event retention`을 핵심 결과로 사용한다.

## 운영 원칙

- 동시에 하나의 실험만 실행한다.
- 각 사용자는 실험 기간 내 같은 변형을 유지한다.
- 실험 시작 전에 기간, 최소 표본, 1차 지표, 보호 지표를 기록한다.
- 중간 지표를 보고 조기 종료하지 않는다.
- 현재 1st-party `analytics_events`만 사용한다. 제3자 분석·실험 SaaS는 추가하지 않는다.

## 1. 첫 가치: 빈 공시함 vs 최근 공시 3건

**가설:** 관심기업을 등록한 직후 최근 공시를 보여주면, 빈 공시함보다 첫
원문 열기와 두 번째 공시 재방문이 늘어난다.

- 대상: 첫 공시 알림 구독을 만든 사용자
- 1차 지표: `historical_filing_opened / filing_subscription_created`
- 2차 지표: 첫 유효 공시 이후 next-event retention
- 보호 지표: SEC 요청 실패율, 첫 공시 감지 지연
- 판단: 적어도 2주와 각 변형의 사전 합의 표본을 채운 뒤 분석한다.

## 2. 푸시 문구: 양식명 vs 사건 유형·알림 이유

**가설:** `8-K 제출`보다 Item·규칙 근거를 포함한 문구가 상세 열기율을
높인다.

- 대상: 즉시 푸시 대상의 신규 공시
- 1차 지표: `notification_clicked / push_provider_accepted`
- 보호 지표: `push_unsubscribed`, 기업 구독 해제, 중복 알림률

## 3. 권한 요청: 첫 기업 vs 세 기업·미리보기 뒤

**가설:** 최근 공시 예시를 경험하고 세 기업을 등록한 뒤 권한을 요청하면
허용률과 테스트 푸시 수신률이 높다.

- 1차 지표: `push_permission_granted / push_permission_prompted`
- 2차 지표: `test_push_received / test_push_requested`
- 보호 지표: 권한 거부율

## 후속 실험 순서

4. 전체 SEC 인덱스 우선 vs 주요 첨부문서 우선
5. 모든 공시 즉시 vs 긴급 즉시·일반 리캡
6. 정정 공시 무시 vs 알림함에서만 원본 비교 제공

모든 실험의 승패와 학습은 이 문서에 날짜, 표본, 효과 크기, 보호 지표와 함께
추가한다. 트래픽이 작아 사전 표본을 채우지 못하면 결과는 `inconclusive`로
남기고 제품 기본값을 바꾸지 않는다.
